# orch — оркестратор ИИ

Схема из видео «Почему ты вайбкодишь неправильно»: **опрос → план → тесты до кода → код до зелёного → оркестратор + изолированные ветки**.

```
Вы ──задача──▶ ДИРИЖЁР (этот Python-код, без ИИ): ведёт процесс, сам гоняет тесты, не верит на слово
                  ▼
           МОЗГ (Fable 5.1): опрос → спецификация → подзадачи + критерии → ревью
                  ▼
   Воркер 1   Воркер 2   Воркер 3      (Opus 5.5, параллельно, каждый в своём git worktree)
       └── тесты КРАСНЫЕ → код → тесты ЗЕЛЁНЫЕ → ревью ──┘
                  ▼
   слияние в ветку orch/<run>/main + полный прогон тестов (регрессия → откат)
```

Подробности и правила — в [SPEC.md](SPEC.md).

## Что нужно

- Python 3.11+
- git
- [Claude Code](https://docs.claude.com/en/docs/claude-code) (`claude`), вход под вашим аккаунтом. Отдельный API-ключ не нужен:
  модели вызываются через `claude -p` от вашей подписки.

## Установка

### Быстрая — через pipx (рекомендуется)

[pipx](https://pipx.pypa.io) ставит консольные утилиты в отдельное окружение и добавляет их в PATH.
Установить сам pipx (один раз, затем перезапустить терминал): на Windows
`python -m pip install --user pipx` и `python -m pipx ensurepath`, на Ubuntu/Debian `sudo apt install pipx` и `pipx ensurepath`.

```bash
pipx install git+https://github.com/sowaaaaa/orcha.git@v0.1.0
orch install-skill
```

Обновление до новой версии: `pipx install --force git+https://github.com/sowaaaaa/orcha.git@<версия>`,
затем снова `orch install-skill`.

### Из исходников — если хотите менять код или запускать тесты

**Windows**
```powershell
git clone https://github.com/sowaaaaa/orcha.git orchestrator
cd orchestrator
python -m venv .venv
.venv\Scripts\python -m pip install -e ".[dev]"
```
Добавьте `...\orchestrator\.venv\Scripts` **в конец** PATH. Тогда `orch` будет доступен везде,
а `python` останется системным, и тесты ваших проектов будут запускаться им.

**Linux**
```bash
git clone https://github.com/sowaaaaa/orcha.git ~/orchestrator
cd ~/orchestrator
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
ln -s ~/orchestrator/.venv/bin/orch ~/.local/bin/orch
```

Проверка: `orch --help`, `claude --version`.

Затем установите навык `/orch` для Claude Code (он запомнит путь к `orch`, так что PATH для чата не обязателен):
```bash
orch install-skill
```

## Работа из чата: `/orch` (основной способ)

1. Откройте папку проекта (можно пустую) в Claude Code: в приложении Claude, вкладка Code, или `claude` в терминале.
2. Напишите один раз: `/orch хочу телеграм-бота, который …`
3. Дальше просто разговаривайте:
   - Claude задаёт уточняющие вопросы. Для новой папки он сам выполнит `orch init`: git, первый коммит, `.gitignore`, `orch.toml`.
   - Он готовит окружение (скелет проекта, тестовый фреймворк, зависимости) и спрашивает разрешение на установку пакетов.
   - Показывает спецификацию и план подзадач. Вы отвечаете «да».
   - Он запускает `orch run --plan … --yes` в фоне. Пока воркеры работают, разговор можно продолжать. На «как дела?» он проверит `orch status`.
   - Пересказывает итог: что готово, что нет и почему. Показывает изменения и спрашивает, вливать ли.
4. Следующая фича — просто напишите её в том же чате. Мелкие правки Claude делает сам, без воркеров.

Навык включается только вашей командой `/orch`. В обычных сессиях Claude работает как всегда.

## Работа из терминала

Проект должен быть git-репозиторием хотя бы с одним коммитом. Для новой папки: `orch init`.

```bash
cd мой-проект
orch run "Добавь регистрацию по email с подтверждением"   # опрос → план → подтверждение → работа
orch run "..." --no-interview --yes                        # без вопросов и подтверждения
orch run "..." --brain claude-opus-5-5 --worker claude-sonnet-5   # другие модели на один запуск
orch run "Название" --plan plan.json --yes                 # готовый план (так делает /orch)
orch status                                                # список запусков
orch status 20260928-101500                                # подзадачи и причины падений
orch resume 20260928-101500                                # доделать упавшее/пропущенное
orch init [папка]                                          # подготовить новую папку
```

Ваша ветка и рабочая папка **не меняются**. Результат — ветка `orch/<run>/main`. Итог подскажет:
```bash
git log --oneline HEAD..orch/<run>/main   # посмотреть
git merge orch/<run>/main                 # забрать
```
Коды выхода: `0` — все подзадачи готовы, `2` — часть упала (см. `orch status <run>`), `1` — ошибка.

## Настройка — `orch.toml` в корне проекта (необязательно)

```toml
[models]
brain = "claude-fable-5-1"
worker = "claude-opus-5-5"

[run]
parallel = 3            # сколько воркеров одновременно
max_test_attempts = 2   # попыток получить красные тесты
max_code_attempts = 3   # попыток кода + ревью

[tests]
full = "npm test"       # полный набор; без этого: package.json → npm test, Python → python -m pytest -q
timeout = 900

[worktree]
link = ["node_modules"] # папки, которые подключаются в каждую копию ссылкой (по умолчанию найденные node_modules/.venv/venv)
setup = ""              # команда подготовки копии, например "npm ci"
```

## Перенос на второе устройство (тот же аккаунт)

Аккаунт Claude общий, но файлы он не синхронизирует. Поэтому:

1. Код лежит в публичном репозитории https://github.com/sowaaaaa/orcha.
   Изменения с первого устройства отправляются туда через `git push`.
   Если на втором устройстве код менять не нужно, хватит быстрой установки через pipx.
2. На втором устройстве (Windows или Linux): установите git, Python 3.11+, Claude Code и войдите тем же аккаунтом (`claude` → `/login`).
3. Выполните шаги из раздела «Установка», включая `orch install-skill`.
4. Обновления: `git pull` в папке оркестратора, затем `orch install-skill` (навык мог измениться).
   Переустанавливать пакет не нужно (`-e`).

Важно:
- **Лимиты общие на аккаунт.** Если оба устройства одновременно запускают воркеров, лимит тратится вдвое быстрее. Уменьшите `parallel`.
- Не запускайте оркестратор на одном и том же проекте с двух устройств одновременно. Синхронизируйте проект через git.

## Безопасность и ограничения

- Модели запускаются с `claude -p --restricted`: без Bash и выполнения команд, без ваших хуков и настроек Claude Code,
  правки только внутри своей копии проекта. Мозг только читает.
- Тесты и команду `setup` запускает дирижёр: это команды из плана или `orch.toml`. Просмотрите план перед подтверждением.
- Воркер не может устанавливать зависимости. Если они нужны, добавьте их заранее или укажите `setup`.
- `.orch/` (состояние, черновики планов, временные копии) исключена из git через `.git/info/exclude`.
  Копии проекта удаляются после запуска. Наработки упавших подзадач сохраняются в ветке `orch/<run>/<id>`.
- Длинные пути на Windows: `git config --global core.longpaths true`.
- Pre-commit-хуки проекта срабатывают и на коммитах воркеров.

## Разработка

```bash
.venv/Scripts/python -m pytest     # Windows
.venv/bin/python -m pytest         # Linux
```
Тесты используют фейковую модель со сценарием и настоящий git: бесплатно, около минуты.
